## 1. Absolute Source of Truth & Zero-Degradation Rule

When a question paper is provided (PDF, JSON, or text dataset):

**The original question paper is infallible and immutable.**

Under NO circumstances may you alter:
- Question wording or phrasing
- Mathematical, scientific, or logical relationships
- Numerical constants, parameters, or values
- Supplied answer choices (A, B, C, D)
- Official correct answer
- Marks awarded and negative marking rules
- Difficulty tier (`EASY` | `MEDIUM` | `HARD` | `ACHIEVER`)
- Target grade/class level (Class 6, 7, 8, etc.)

> [!IMPORTANT]
> **The interactive activity is exclusively a visual, spatial, and procedural delivery mechanism.**
> It never replaces, alters, or dumbs down the examination question.

## 2. The Anti-Copying & Generative Invention Manifesto

> [!CAUTION]
> **STRICT DIRECTIVE: NEVER COPY EXISTING BLUEPRINTS OR QUESTIONS VERBATIM.**
> The 50 reference blueprints in our knowledge base (such as the Olympiad 1 set) are **Abstract Cognitive Paradigms & Architectural Patterns**, NOT a static library to copy-paste.

When asked to create activities for any new question or paper:
1. **Never copy-paste** the specific scenario or mechanics from previous questions.
2. **Never reuse identical metaphors** (e.g. if Q1 used a 3D Dice table, do not use another 3D Dice table for a different dice question without inventing a fresh, tailored mechanic).
3. **Always think with AI from first principles**:
   - Ask: *"What is the core cognitive tension in this exact problem?"*
   - Ask: *"What unique microworld, machine, laboratory, simulation, or physical apparatus represents this exact mathematical or logical phenomenon?"*
   - Ask: *"How can a Class 6–8 child interact with this in 15–60 seconds on a standard touch/desktop screen?"*
4. **Scale to 500–1000+ Questions**: Across Class 6, Class 7, Class 8, across 6–8 subjects and dozens of papers, every single activity must feel bespoke, fresh, and globally unique.

## 4. The `OlympiadActivity` Data Architecture & Contract

Every activity created must conform to this complete data contract:

```typescript
export interface OlympiadActivity {
  /** Unique activity instance ID: `act_{questionId}_{timestamp}` */
  id: string;

  /** Source question ID (e.g., "LOG-G6-001", "MAT-G7-024") */
  questionId: string;

  /** Canonical paper identifier */
  paperId: string;

  /** Activity family categorization */
  family:
    | "simulation"
    | "construction"
    | "investigation"
    | "spatial"
    | "classification"
    | "measurement"
    | "navigation"
    | "visual-puzzle"
    | "data"
    | "transformation"
    | "mechanical"
    | "other";

  /** Engaging, child-friendly title */
  title: string;

  /** One-line conceptual description of the experience */
  concept: string;

  /** Interaction mechanics and supported input modalities */
  interaction: {
    type: string;
    inputs: ("mouse" | "touch" | "keyboard" | "drag" | "dial" | "slider" | "click")[];
  };

  /** Technology engine utilized */
  renderer: "svg" | "canvas" | "three" | "babylon";

  /** Viewport scene configuration */
  scene: {
    width: number;
    height: number;
    background: string;
    responsive: boolean;
  };

  /** Animation & motion choreography */
  animation: {
    intro: string;
    interaction: string;
    success: string;
    failure: string;
  };

  /**
   * CRITICAL: The activity is a presentation capture layer.
   * It maps student interaction to the source question options.
   * It NEVER determines official examination marks directly.
   */
  answerMapping: {
    activityAnswer: unknown;
    sourceOption: "A" | "B" | "C" | "D" | string;
    mappingLogic: string;
  };

  /** Target interaction duration (15–60 seconds) */
  estimatedTimeSeconds: number;

  /** Universal accessibility and hardware support */
  touchSupported: boolean;
  keyboardSupported: boolean;
  minTouchTargetPx: number; // Must be >= 44
}
```

### The 4-Tier Diversity Rules for Any 50-Question Paper:
1. **Max 3 Uses Per Specific Mechanic**: No specific interaction mechanic may appear more than 3 times in one paper.
2. **Family Balance**:
   - 8–12 Simulations
   - 8–12 Spatial / Manipulation activities
   - 5–8 Construction activities
   - 5–8 Puzzle & Deduction activities
   - 4–6 Physical system activities
   - 4–6 Visual pattern activities
   - 3–5 Graph / Coordinate activities
   - 3–5 Real-world scenario activities
3. **No Consecutive Twins**: Never use the same family or primary interaction pattern in adjacent questions.
4. **Persistent Global Ledger**: Every newly implemented activity must be logged into `src/olympiad/activities/history.json` and registered via `registerActivity()`.

## 6. The Mandatory "WOW Test" & Quality Gates

Before accepting any activity design, run this internal validation matrix:

### The 4 WOW Test Questions (Must score at least 3/4 YES):
1. *If the text prompt was hidden, would a child immediately recognize an intriguing, interactive world?*
2. *Does the interaction make the student genuinely want to touch, move, or operate it?*
3. *Does the physical/visual movement authentically represent the mathematical/logical concept?*
4. *Will the student still remember the visual phenomenon 1 hour after the exam?*

### Quality Gate Thresholds:
| Evaluation Criterion | Minimum Score | Enforcement |
|---|---|---|
| **Answer Fidelity** | **10 / 10** | **MANDATORY** (Zero tolerance for math/logic distortion) |
| **Exam Suitability** | **8 / 10** | **MANDATORY** (Must complete in 15–60s without frustration) |
| **Conceptual Relevance** | **8 / 10** | **MANDATORY** (Metaphor must teach the concept) |
| **Uniqueness Score** | **≥ 8 / 10** | Reject if repetitive compared to registry |
| **Student Delight** | **≥ 8 / 10** | Must feel premium, modern, and engaging |
| **Clarity of Goal** | **≥ 8 / 10** | Zero ambiguous or confusing UI controls |

## 7. The 12-Step Autonomous Creation Pipeline

When invoked via `/olympiad` or when processing questions:

```
STEP 1:  Ingest Source Question  ──► Freeze text, options, answer, difficulty, marks.
STEP 2:  Cognitive Extraction    ──► Identify the core mathematical/logical invariant.
STEP 3:  Tri-Concept Ideation    ──► Brainstorm 3 radically different interaction worlds.
STEP 4:  Purge Generic Tropes    ──► Reject plain MCQs, generic quizzes, and lazy drag-drops.
STEP 5:  Registry Conflict Check ──► Query `history.json` for anti-repetition compliance.
STEP 6:  Execute WOW Test        ──► Score all 4 criteria; select highest-scoring concept.
STEP 7:  Draft Activity Blueprint──► Generate full `OlympiadActivity` specification.
STEP 8:  Build Answer Mapping    ──► Decouple presentation state from evaluation score.
STEP 9:  Tech & Ergonomics Check ──► 2D first (SVG/Canvas), touch ≥ 44px, 15–60s pace.
STEP 10: Code Implementation     ──► Build component implementing `ActivityContract`.
STEP 11: Unit & Scoring Test     ──► Validate answer fidelity across all 4 options (A, B, C, D).
STEP 12: Registry Enrollment     ──► Write activity metadata into `history.json`.
```
